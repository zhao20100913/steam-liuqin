# 03 决策清单（需要用户确认）

每项给推荐选项与理由；确认后写入 `AGENTS.md` 并开始第 1 步。确认前不碰设备。

## D1. SteamOS 底包来源

- **A（推荐）** 直接用 Valve 官方 Steam Frame 恢复镜像：`steamframe-repair-latest.img.bz2`（约 4 GB，公开直连），并用 `zhao20100913/steamos-liuqin1` 的取包脚本按 GPT 切出 `rootfs-A`。
- B 用用户文件夹里的那份 SteamOS 发行版（需要先上传到本机 `/sdcard/Download`，并说明它是什么：整盘镜像 / rootfs 压缩包 / 已解包目录）。

理由：A 的版本、校验与取包路径都可复现；若 B 是同一来源的副本，也应先报哈希再决定。

## D2. 安装布局

- **A（推荐）** `dual`：保留 Android，`userdata` 缩到 96 GiB，`linux_root` 32 GiB，`linux_home` 剩余；两个系统都从 A 槽启动，切换时换 `boot_a`。已真机验证。
- B `linux-only`：SteamOS 装 B 槽，A 槽留作应急 Android（`--android-size` 保留 ≥16 GiB）。
- C 全盘单系统：不给 Android 留空间；恢复 Android 成本最高。

理由：dual 已被验证，且 SteamOS 的游戏库可以放 `linux_home`，32 GiB 根足够。

## D3. 启动链

- **A（推荐）** 复用 yzddmr6 v0.6.0 的 `boot.img`（内核 6.17 + liuqin DT + initramfs）与 `installer.img`/`install.py`/`liuqin_layout.py`，只替换 rootfs 载荷与系统切换入口。
- B 自己重建 boot 镜像集（换内核或改 cmdline 时走这条）。
- C ROCKNIX ABL：**不做**（无 SM8475/liuqin 支持）。

## D4. 根文件系统形态

- **A（推荐）** ext4 单根，沿用 yzddmr6 的布局；把 Frame 的 rootfs 树铺进去，`/home` 挂 `linux_home`。停用 `steamos-update`（A/B 更新不可用）。
- B btrfs + SteamOS 原生子卷（`rootfs`/`var`/`home`）：更接近 SteamOS 更新模型，但安装器、分区表与 boot 都要改，风险与工期显著增加。

理由：先求跑起来；更新能力后置，且 Valve 镜像的 A/B 机制本来就要按设备重做。

## D5. 首版范围

- **A（推荐）** 首版只承诺：开机进 Game Mode、Steam 登录、ARM64 游戏可玩、桌面模式可用、Wi-Fi/蓝牙/音频/亮度/触控可用、可切回 Android。
- B 首版就加指纹、DP、相机、休眠完善（按 D5-A 的路线逐个后补）。

## D6. 调试通道

- **A（推荐）** USB NCM 网络 + SSH，默认关闭、可显式打开；首次刷入测试机前先打开并验证退路。
- B 常开（不推荐：安全面与功耗）。

## D7. 发布与合规

- **A（推荐）** 先私有验证，不公开发布；公开发布时只发构建脚本、内核 diff 与文档，不打包再分发 Valve 二进制与固件。
- B 直接发布整包（需要先解决 Valve/固件许可，且与「不侵权」目标冲突）。

## D8. 数据与备份范围

- 安装会清空 userdata。确认：
  - [ ] 平板内个人数据已备份到设备以外；
  - [ ] 已准备匹配防回滚要求的原厂 Fastboot ROM；
  - [ ] 接受备份 `boot_a`、`boot_b`、`persist`、主备 GPT（安装器会自动做，另存一份）；
  - [ ] 明确「恢复 Android」的人工步骤与责任人。

## D9. 谁在什么时候操作真机

- 构建、取包、改脚本可以在任何机器上无人值守做；
- **刷写、分区、首次启动、按键确认必须用户在场**，且同一时刻只有一个操作者（见 `AGENTS.md`）。
- 若用户希望我远程指导，按「我出命令 → 用户执行 → 回传输出」的节奏，不代操作。
