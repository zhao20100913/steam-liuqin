# 09 · 刷入执行清单（真机第一测）

> 目标：把 `v0.1.0-pre2` 的 SteamOS 装进小米平板 6 Pro，第一次开机进 TTY，验证内核/存储/网络。
> 这是**两步装**：先有 Ubuntu 双系统（上游 v0.6.0 的功劳），再把 `linux_root` 换成 SteamOS。
> 全程有人在平板旁；每一步失败就停，先看证据再决定回滚。

## 起点判断

```bash
# 平板进 fastboot，PC 上执行
fastboot devices
fastboot getvar unlocked        # 必须是 yes
```

| 平板现状 | 从哪一步开始 |
|---|---|
| 还是原厂 Android，没装过 Linux | 第 1 步 |
| 已能进 Ubuntu 双系统，`lsblk` 有 `linux_root` + `linux_home` | 第 2 步 |

已经刷过别的 Linux、分区名对不上 → 先用上游 `install.py --restore-partition-table` 回原厂布局，再走第 1 步。

## 准备

- PC：Linux / macOS，装好 `adb` + `fastboot`（Android platform-tools）
- 平板：电量 ≥ 50%，原装或能传数据的 USB 线
- 个人数据已备份到平板以外（第 1 步会清空 `userdata`）
- 上游 v0.6.0 的 `boot.img` 另存一份（回滚用）

## 第 1 步：装 Ubuntu 双系统（仅当还没有）

### 1.1 下载

- 上游 Release v0.6.0 全部资产：<https://github.com/yzddmr6/xiaomipad-6pro-mainline/releases>
- 原厂 Fastboot ROM：`OS2.0.6.0.VMYCNXM`（版本必须与 `liuqin-rom-images.json` 一致，低了会被防回滚拒绝）
- 解包 ROM，得到 `images/` 目录

### 1.2 执行

```bash
mkdir -p ~/liuqin-install && cd ~/liuqin-install
# 把 Release 里除分卷外的文件放这里，再合并分卷
cat rootfs.tar.gz.part-* > rootfs.tar.gz

python3 install.py --bundle . \
  --serial <平板序列号> \
  --backup ~/liuqin-backup-new \
  --erase-userdata \
  --layout dual \
  --rom-dir ~/rom/images \
  --android-size 96G --root-size 32G
```

- 会交互要求输入 `YES` 确认清空数据
- 安装器临时启动 `installer.img`，等它自己跑完（约 30–60 分钟，别拔线）
- 成功后自动进 Ubuntu；`installer.img` 只是临时启动，不落盘

### 1.3 进 Ubuntu 后确认

```bash
lsblk -o NAME,PARTLABEL,SIZE | grep linux
# 期望：linux_root ≈32G、linux_home = 剩余
```

## 第 2 步：在 Ubuntu 里换根

### 2.1 把脚本送进平板

平板联网后二选一：

```bash
# 方式 A：平板能访问 GitHub
curl -fLO https://raw.githubusercontent.com/zhao20100913/steam-liuqin/main/device/stage-steamos.sh

# 方式 B：PC 下载后 scp / U 盘拷进去
```

### 2.2 执行

```bash
sudo bash stage-steamos.sh \
  https://github.com/zhao20100913/steam-liuqin/releases/download/v0.1.0-pre2
```

脚本做的事（都会打印）：

1. 确认 `linux_root` / `linux_home` 存在
2. 下载 3 个分卷 + `parts.sha256` 并校验
3. 格式化 `linux_home`（原 Ubuntu `/home`，**会被清空**）为 ext4，标签 `LIUQIN_ROOT`
4. 解包 SteamOS 到该分区
5. 互换 GPT 分区名：旧根 → `linux_home`，新 SteamOS → `linux_root`

> 平板若连不上 `github.com`：PC 上 `python3 -m http.server 8000` 起在放分卷的目录，
> 把 URL 换成 `http://<PC 局域网 IP>:8000`。

看到最后的 `完成。现在用 PC 刷 boot_a` 就停，**先别重启**。

## 第 3 步：PC 刷 boot

```bash
adb reboot bootloader
fastboot devices
fastboot flash boot_a boot-steamos-liuqin.img
fastboot reboot
```

- 只刷 `boot_a`，`boot_b` 保持上游 Ubuntu 的回退镜像
- 刷之前确认文件是 `19,357,696 B`，sha256 对得上
- 想留在 Android：刷回 Android 的 boot.img（见回滚）

## 第 4 步：首启（默认 TTY/SSH，不是桌面）

构建默认 `debug_boot=1` → `multi-user.target`。第一次**屏幕可能是黑的或停在启动日志**，这是预期。

进入方式（任一）：

- 磁吸键盘 / USB-OTG 键盘：`Ctrl+Alt+F2` 拿 TTY
- SSH：平板连网后，PC `ssh steamos@<平板 IP>`，密码 `steamos`
  - 平板没网就先在本地 TTY 里 `nmcli device wifi connect <SSID> password <密码>`

逐项验证（一次一项，失败就停）：

```bash
uname -a                                  # 6.17.0-rc1-gfe81794b5e1b
cat /etc/os-release                       # ID=steamos, VARIANT_ID=vr
ls /lib/firmware/qcom/sm8475/liuqin/      # a730_zap.mbn adsp.mbn ...
ls /usr/lib/modules/                      # 只有 6.17.0-rc1-gfe81794b5e1b
dmesg | grep -iE 'adreno|panel|novatek|wcd938x' | head
ip a; ping -c1 1.1.1.1
systemctl --failed
```

## 第 5 步：试图形（TTY + 网络都通过后再做）

```bash
sudo systemctl set-default graphical.target
sudo reboot
```

首轮大概率起不来完整桌面（显示栈/固件适配未做）。黑屏就：

- `Ctrl+Alt+F3` 回 TTY
- 或 SSH 进去 `systemctl status sddm`、`journalctl -b -u sddm`

**不要**在这一步反复重启超过两次；先抓日志。

## 回滚

| 想回到 | 做法 |
|---|---|
| Ubuntu（还没重启） | 在 Ubuntu 里 `sudo bash stage-steamos.sh --rollback` |
| Ubuntu（已刷 boot，起不来） | `fastboot flash boot_a <上游 v0.6.0 boot.img>` |
| Android | 先确认 `/home/var/lib/liuqin/switch/android/boot.img` 存在，再 `fastboot flash boot_a` 它 |
| 原厂布局 | 上游 `install.py --restore-partition-table <备份目录>`，然后重装 |

> 换根后旧 Ubuntu 根挂在 `/home`，Android 的 boot.img 就在
> `/home/var/lib/liuqin/switch/android/boot.img`。刷之前先 `ls` 确认，别猜路径。

## 这次测试要回答的问题

1. 内核能不能起来（串口/屏幕日志、`uname`）
2. `linux_root` 能不能被我们的 init 找到并 switch_root
3. 固件能不能加载（adsp / a730_zap / 触控）
4. 网络（Wi-Fi 或 USB RNDIS）
5. 显示子系统离「能点亮」还差多少（`dmesg` 里 panel/DSI 报错）

把 `dmesg`、`systemctl --failed`、`journalctl -b` 三份输出带回来，就是下一轮的输入。
