# 05 构建路线（从输入到可刷镜像）

目标产物：一份可被 yzddmr6 安装器写入 `linux_root`/`linux_home` 的 SteamOS 根文件系统载荷 + 与之匹配的 `boot_a/boot_b` 镜像，真机双系统启动进 Game Mode。

所有步骤在 Linux 构建机执行；本机（Android 手机）只保存文档与脚本，不执行。

## S0. 固定输入（先写 `inputs.lock`）

| 输入 | 固定方式 |
|---|---|
| liuqin 内核 | `linux-sm8450-liuqin` @ `fe81794b5e1b8a3f11a165f3acbfdb8fa671dbb3`（分支 `liuqin-6.17`） |
| 内核配置片段 | `xiaomipad-6pro-mainline/device/configs/liuqin-*.config`，按文件哈希固定 |
| boot / installer | v0.6.0 Release 资产，记 sha256（`boot.img` 50,216,960 B；`installer.img` 58,679,296 B） |
| Steam Frame 底包 | `steamframe-repair-latest.img.bz2` 或版本化 `steamframe-oobe-repair-20260922.5153644-0.3.0.img.bz2`，记 sha256 与 `os-release` |
| 参考脚本 | `steamos-liuqin1` 的 `00-fetch-frame-rootfs.sh` 等，记 commit |

产出：`inputs.lock`（JSON），后续每步先校验。

## S1. 取底包并切分区

用 `00-fetch-frame-rootfs.sh` 的两遍流式法（不落 4 GB bz2）：

1. 第 1 遍只取前 4 MiB 解 GPT；
2. 第 2 遍 `curl | bunzip2 | dd` 精确切出 `rootfs-A`（btrfs，约 5 GB）。

校验：`file` 显示 btrfs 超块 `_BHRfS_M` 在 65536；`blkid` label = `rootfs-A`；记录 `os-release`。

## S2. 装配 SteamOS 根文件系统

1. `mount -o loop,ro rootfs.frame` 可读（btrfs 子卷根可能是 `.` 或 `@`，脚本会探测）。
2. 目标布局：`linux_root`（ext4, 32 GiB）+ `linux_home`（ext4, 剩余）→ 对应 `/` 与 `/home`。
3. 从 Frame rootfs 拷入系统树；保留 `/usr`、`/etc`、`/var` 骨架。
4. 从 liuqin Ubuntu rootfs 取：
   - `/lib/modules/<6.17.*>` 与 `/lib/firmware`（含 `qcom/sm8475/liuqin/*`、`novatek/liuqin/*`）；
   - `liuqin-speakers.m4` 音频拓扑与 UCM；
   - 面板/触控固件与任何 liuqin 专有配置。
5. SteamOS 适配：
   - 建 `steamos` 用户与组，设置默认会话；
   - 停用 VR/Frame 专属服务与 `steamos-update`（TD-01/TD-02 清单）；
   - 配 gamescope 默认分辨率/缩放与触摸输入；
   - 写入 `os-release` 的本项目标识，保留 SteamOS 标识以免 Steam 客户端行为异常。

产出：`rootfs.tar.gz`（或安装器期望的归档形态）+ 文件清单 + sha256。

## S3. 启动镜像

- 默认沿用 v0.6.0 的 `boot.img`（内核/DTB/initramfs 已匹配 liuqin，且验证过冷启动）。
- 仅当内核配置需要改动（S2 发现缺模块/驱动）时，用内核仓 `tools/build-liuqin-kernel.py` 重建，按同格式重打 boot 镜像。
- 校验：boot 头类型、cmdline、DTB 名 `qcom/sm8475-xiaomi-liuqin.dtb`；与安装器的校验逻辑一致。

## S4. 安装器整合

- 复用 `install.py` + `liuqin_layout.py`：分区、备份、写 rootfs、刷 boot 的逻辑不动；
- 把「下载并校验 Ubuntu 归档」换成「本项目载荷 + 校验」；
- 双系统切换入口（KSU 模块）改名并指向 SteamOS；
- 先在内存/临时启动（installer.img）里验证，不直接写内部存储。

## S5. 真机验收（每项都有判据）

1. 冷启动 → Game Mode 出现在内置屏；
2. 触控可用、亮度可调；
3. Steam 登录成功，商店/库加载；
4. ARM64 游戏可启动；x86 游戏经 FEX+Proton 可启动；
5. 桌面模式可切，Wi-Fi/蓝牙可用；
6. 音频四扬声器、音量键；
7. 切回 Android 一次，再切回 SteamOS 一次；
8. 断电重启 3 次均进 SteamOS；
9. 失败时能从备份恢复（演练一次）。

## S6. 发布（在 D7 确认后）

- 只发脚本、内核 diff、文档与校验和；
- 安装文档按「全新机器从零装」写，并在真机走一遍；
- 支持表只写已验证项。

## 追加决定（2026-11-03，实现后回填）

- **不改上游装机器**：`initramfs/init` 对 installed root 有 Ubuntu 专属契约验收（GNOME guard / snap admission / power-keyd / sensor-stack / gdm3 软链 / 多个 755 可执行文件），SteamOS 树不可能满足，改它成本高于收益。
- **两步安装**：上游 v0.6.0 装 Ubuntu 双系统 → `device/stage-steamos.sh` 把 SteamOS 铺到 linux_home 并互换 GPT 分区名 → `fastboot flash boot_a boot-steamos-liuqin.img`。
- **自建 boot.img**：`scripts/make-boot-img.sh` 取上游 kernel + dtb，套 `boot/init`（busybox，只认 `PARTNAME=linux_root`，mount 后 switch_root）。内核/固件版本仍与底包一致，vermagic 不会错。
- CI 在 `ubuntu-24.04-arm` 上一条龙产出分卷 + boot.img（`.github/workflows/build.yml`）。
