# 08 · 首轮 CI 构建报告（2026-11-09）

> 结论：**流水线跑通了**。在 GitHub 的 `ubuntu-24.04-arm` runner 上，从零到可安装产物全自动，
> 单次约 13 分钟。产物已发布为 Release：`v0.1.0-pre2`。

## 跑了几次、每次为什么失败

| # | 结果 | 失败点 | 修复 |
|---|---|---|---|
| 1 | ❌ | `pip install mkbootimg` → `No matching distribution found`（runner 上 PyPI 不可达） | 改写纯 Python boot.img v2 重打包器 `scripts/mk-bootimg.py`，复用上游头部，零依赖 |
| 2 | ❌ | `fetch-frame.sh` 把 bunzip2 的 SIGPIPE 当成失败（`rc=1`） | 关掉 pipefail，只看 `PIPESTATUS[2]`（dd 自己） |
| 3 | ❌ | `assemble-rootfs.sh` 用 `usr/lib/os-release` 找根子卷，Frame 镜像顶层就是根 | 判据放宽到「etc + usr 目录」 |
| 4 | ❌ | rsync `-X` 把 btrfs.* xattr 写到 ext4 上 → code 23 | 去掉 `-X`（rsync 3.2.7 没有 `--xattrs-exclude`） |
| 5 | ✅ | — | 首次全绿；产物 5.4 GB |
| 6 | ✅ | — | 补 mask Frame 专用服务、清 Frame 内核模块、勘察图形会话；并把 boot.img 加进 Release |

## 产物（v0.1.0-pre2）

| 文件 | 大小 | 说明 |
|---|---|---|
| `boot-steamos-liuqin.img` | 约 19 MB | 上游 6.17 内核 + 我们的 dtb + 自建 busybox initramfs（按 `PARTNAME=linux_root` 找根） |
| `steamos-liuqin-rootfs.tar.gz.part-00/01/02` | 2.0 GB + 2.0 GB + 1.18 GB | SteamOS 树（gzip -1），`cat` 合并后约 5.18 GB |
| `*.sha256` | 117 B | 校验 |

rootfs 内容规模：**10 GB**（`/usr` 8.6 G，`/opt` 1.3 G），其中 SteamOS 用户态来自 Steam Frame 的 `rootfs-A`（btrfs）。

## 勘察到的“Frame 用户态”事实

```
NAME=SteamOS  VARIANT_ID=vr  VERSION_ID=0.3.0  BUILD_ID=20260922.6152327
ID_LIKE=arch（holo），有 pacman
```

- **有**：`steam`、`gamescope`、`plasmashell`、`kwin_wayland`、`Xwayland`、`sddm`、`startplasma-wayland`、`steamos-session-select`
- **没有**：`fex`、`box64`、`wine` → **x86 游戏暂时跑不了**（Steam Frame 的 x86 兼容层不在这个镜像里，得另加 FEX + Proton）
- Vulkan：`freedreno_icd.aarch64.json` + `libvulkan_freedreno.so` 在 → Adreno 有现成 ICD，方向对
- Wayland 会话：
  - `gamescope-wayland.desktop` → `start-gamescope-session gamescope-session.target`
  - `plasma.desktop` → `start-gamescope-session plasma-session.target`
- 用户：UID 1000 已存在（`steamos`），组 `wheel/audio/input/render/video` 都已含它
- 内核模块目录：只保留了 `6.17.0-rc1-gfe81794b5e1b`（来自 v0.6.0 底包，与 boot.img 同源）；Frame 自带的 `7.0.0-14-generic` 已删

## 已做的适配（configure 阶段）

- `/etc/fstab`：`PARTLABEL=linux_root /`、`PARTLABEL=linux_home /home`、tmpfs `/tmp`
- hostname `liuqin`
- 首启 `default.target → multi-user`（调试期），SSH 开
- mask 掉依赖 Valve 服务器或 Frame 硬件的 unit：
  - 更新链：`steamos-update` / `atomupd*` / `rauc` / `bootc-fetch-apply-updates` / `steamos-manager` / `steamos-boot`
  - Frame 硬件：`deckard-*`（FPGA/风扇/LED/充电/电源监测/typec）、`dsp_service`、`steamvr-*`、`gpu-trace`、`iris-driver-rebind`、`setubootenv`、`usb-gadget`、`adbd*`

## 还没解决的（按优先级）

1. **图形栈首启**：默认 multi-user，验证 TTY/SSH 后再 `systemctl start sddm`；Frame 的 `start-gamescope-session` 是否能在 liuqin 上起 plasma，未知，要真机试。
2. **x86 游戏**：缺 FEX/box64/Proton，需要从 CachyOS/armada 之类抓 aarch64 构建，或接 Steam 的 ARM 运行时（待调研）。
3. **Wi-Fi/触控/音频/亮度**：依赖 liuqin 6.17 内核 + 固件（已注入），但首启能否驱动起来要真机验证；DP 外接同理。
4. **dmesg/固件缺失**：`a730_zap/adsp/novatek` 已确认在树里，其余固件（WCN6855 等）来自 v0.6.0 底包，未逐个核对。
