# 00 可行性评估（第 0 步）

日期：2026-11-03 · 版本：v0.1（立项，未碰设备）

## 任务

在 Xiaomi Pad 6 Pro（liuqin，SM8475）上运行 Valve 的 ARM64 SteamOS（Steam Frame 用户态），达到：开机进 Game Mode、能登录 Steam、能玩 ARM64 原生游戏与 x86 游戏（FEX + Proton）、可切回 Android 双系统。

## 结论摘要

**技术上可行，而且比通常的主线移植起点高很多**：liuqin 已有一份真机全功能验收的主线内核与完整安装链，本项目的核心工作从「让 Linux 启动」变成「把 SteamOS 用户态装到一台已经能跑 Linux 的平板上」。

| 判断 | 依据 |
|---|---|
| 内核不是瓶颈 | `yzddmr6/linux-sm8450-liuqin`（`liuqin-6.17`，commit `fe81794b`）在 Ubuntu 0.6.0 中已验证：显示 2880×1800@120、触控、GPU 加速、Wi-Fi/蓝牙、四扬声器、麦克风、指纹、磁吸键盘、DP 外屏、充电 |
| 启动链不是瓶颈 | 同项目 v0.6.0 提供 `boot.img`、`installer.img`、分区布局引擎与双系统切换，均在 256 GB 真机验证过 |
| 用户态是主战场 | Steam Frame 镜像是 VR 一体机系统：VR 服务、OOBE、更新通道、电源策略都按 Frame 硬件写死，需要裁剪/替换为平板形态 |
| 主要不确定项 | Frame 用户态能否在非 VR 设备上走到 Game Mode；Adreno 730 的 Turnip/Mesa 组合；cs35l41 音频在 PipeWire 下的 UCM；触摸/键盘在 gamescope 下的输入映射 |

## 三条路线

### A. 原生 SteamOS（推荐）

Frame 的 btrfs rootfs → 装到 liuqin 的 `linux_root`（ext4）→ 换 liuqin 内核模块与固件 → 裁 VR 服务、加平板配置 → 用 yzddmr6 的 `boot.img`/安装器启动。

- 优点：复用最多已验证资产；Game Mode、FEX、Proton 都是 Valve 现成的；双系统可保留 Android。
- 代价：SteamOS 的 A/B 更新机制不可用（ext4 单根），必须停用并说明；Frame 特有服务要逐个处理。
- 参考实现：[SteamOSforAlioth](https://github.com/ShouChenICU/SteamOSforAlioth)（SM8250 手机直接进 Game Mode）、[SteamOS-ARM-Port](https://github.com/hashtagbasit/SteamOS-ARM-Port)（按 SoC 出镜像，含掌机/平板调优）、[steamos-liuqin1](https://github.com/zhao20100913/steamos-liuqin1)（已有的 liuqin + Frame 装配脚本，但未真机验证）。

### B. ROCKNIX ABL 路线（不推荐）

SteamOS-ARM-Port 的做法是刷 ROCKNIX ABL，开机菜单选设备型号再引导 Linux。

- 不支持：其镜像只覆盖 SM8550 / SM8650 / SM8750，ABL 也没有 liuqin 设备项；SM8475 没有现成移植。
- 额外风险：刷 ABL 本身就会改启动链，失败恢复成本高于本项目需要的程度。
- 结论：不作为主线；若将来社区 ABL 支持 SM8475，可作为「免分区试运行」的补充。

### C. Android 容器方案（备选，不作为主线）

在 Android 上以 chroot/容器跑 SteamOS 用户态（参考 DroidSpaces 类项目）。

- 优点：不解锁、不改分区、可随时删。
- 缺点：没有 KMS/gamescope 原生会话，GPU 走 Android 的 KGSL 路径，Game Mode 基本不可用；性能与体验都达不到「移植」的目标。
- 结论：只作为「先看看 Steam 界面」的临时手段。

## 主要风险（按影响排序）

1. **Frame 用户态的设备假设**：OOBE、`steamos` 用户、Steam 客户端、`steamos-update`、电源/待机服务都假定 Frame 硬件。需要在 chroot 里逐项关掉/替换，且没有官方文档。
2. **GPU**：Frame 用户态的 Mesa/Turnip 面向其 SoC；Adreno 730 需要对应固件（`a730_zap.mbn` 等，liuqin 固件包已有）与足够新的 Turnip。能否直接复用、是否需要换 Mesa 版本，是本项目最大的技术未知。
3. **显示/输入**：2880×1800@120、双 DSI + DSC；gamescope 需要正确的 mode 与缩放；平板没有内置手柄，触摸在 Game Mode 下只是指针，实际游戏需要蓝牙手柄。
4. **音频**：四颗 CS35L41 + WCD938x，SteamOS 用 PipeWire/WirePlumber；需要把 liuqin 的 UCM/拓扑装进 SteamOS 并验证。
5. **更新与回滚**：SteamOS 的 A/B 更新在 ext4 单根下不可用；必须停用系统更新，否则更新会把系统写坏。
6. **解锁与数据**：解锁 Bootloader 会清数据；双系统安装还会清 userdata 并改写分区表（已由 yzddmr6 的安装器验证边界：4096 字节逻辑扇区、userdata 为最后一个分区、仅 256 GB 布局）。
7. **分发合规**：Valve 镜像与其组件有各自许可；对外只发布构建脚本与自有改动，不打包再分发 Valve 二进制。

## 工作量估算（单人，有真机 + Linux 构建机）

| 阶段 | 内容 | 估计 |
|---|---|---|
| 1 | 构建环境 + 复现 liuqin 内核与 Ubuntu 基线 | 3–5 天 |
| 2 | Frame rootfs 提取、裁剪、装进 liuqin 布局，chroot 起 systemd | 1–2 周 |
| 3 | 首次点亮：Game Mode / 桌面会话跑起来 | 1–2 周 |
| 4 | GPU、显示模式、输入映射 | 1–2 周 |
| 5 | 音频、Wi-Fi/蓝牙、电源与待机 | 1–2 周 |
| 6 | 安装器整合、双系统切换、冷启动回归、文档与发布 | 1–2 周 |

合计约 **6–10 周**（含返工）；最大不确定项是第 3、4 阶段，若 Frame 用户态对 GPU 的要求无法满足，可能需要换 Mesa/Turnip 版本或改用 SteamOS-ARM-Port 的 per-SoC 方案。

## 前置条件（缺一不可）

- 已解锁 Bootloader 的 Pad 6 Pro（liuqin），电量 ≥ 30%，原厂 Fastboot ROM（防回滚版本）在手。
- Linux 构建机：x86_64 或 arm64，≥ 100 GB 空闲，≥ 16 GB 内存；能跑 `qemu-user-static`/binfmt（装配 arm64 rootfs 用）。
- 平板以外的工作备份；明确接受清空 userdata。
- 用户确认 `docs/03-决策清单.md`。
